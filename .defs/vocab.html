The dr-graph computation-graph contract

A reference for the terms and guarantees that bind dr-graph.

dr-graph · 2026-07-24

This is the vocabulary of the computation-graph contract dr-graph implements: the terms for graph shape, config identity, and deterministic interpretation, the guarantees that bind this repo, what is in and out of scope, and the mapping from each term to the names actually exported by dr_graph. This repo provides hashable graph configs and a pure interpreter; it is not a workflow engine, and durability, scheduling, and domain semantics belong to the caller.

Terms

TermDefinition
NodeAn executable component of a graph with declared input fields and output fields, connected to other nodes so that outputs route to inputs. The umbrella structural component; graph configs and node configs specialize it.
Directed Acyclic Graph (DAG)A set of nodes connected by directed edges with no cycle, so that following edges never returns to a starting node.
Topological OrderA linear ordering of a DAG's nodes in which every node appears after all the nodes it depends on. Ties are broken by node id, so the order is deterministic.
Sink NodeA node whose output no other node consumes. A graph in this repo has exactly one, which fills the graph's terminal-node role.
PayloadThe inner data a document carries, distinct from the schema name and version that wrap it.
Schema and Schema VersionA name identifying the shape of a document and an integer marking a specific revision of that shape. Changing the version changes every hash computed from documents of that schema.
Finite JSONA JSON value composed only of null, booleans, strings, finite numbers, lists, and string-keyed objects, recursively — with no NaN, no infinities, and no other runtime type. This repo validates it and rejects everything else.
Canonical JSONThe single deterministic UTF-8 JSON rendering of a JSON-safe value — compact, sorted keys. The same value always produces the same bytes.
ValidationThe check that a value conforms to its declared shape and rules, accepting it unchanged or raising a typed error. Constructing a config or document validates it.
Node Runner CallbackA caller-supplied function that the interpreter invokes once per node to produce that node's output. It holds all domain behavior; the interpreter never inspects what it does.
HashA deterministic fixed-length value computed by a declared algorithm over exact declared input bytes; its specific role and semantics come from the qualified term. This repo computes the graph hash specialization.
VariableA named slot on a node whose allowed values and identity effect a graph definition declares, set to a concrete value when a graph config is materialized.
GraphA directed acyclic composition of nodes whose connections route outputs to inputs. The umbrella structural concept that graph definitions and graph configs specialize.
Graph DefinitionA versioned, variable-bearing graph shape. It declares node definitions, variables, structure, input and output contracts, and exactly one terminal node, and materializes one or more graph configs. The definition carries its own integer schema_version for the definition artifact's shape, independent of GRAPH_CONFIG_IDENTITY_SCHEMA_VERSION, and it never enters the graph hash (a materialized graph config holds only its nodes and terminal node id).
Node DefinitionThe declaration of one node within a graph definition: its node id, its node type reference, declared input and output fields, its node input sources fixing the DAG shape, and the names of the variables a graph config must set for it.
Graph ConfigA concrete, fully set and validated config materialized from exactly one graph definition. Its nodes carry their node type reference, every static variable assignment that determines identity, node input sources, and its declared output field. It has exactly one terminal node and is the sole config identifying one rollout variant. Its exact versioned identity document produces the graph hash.
MaterializationOne fully-set graph config produced from a graph definition, with a concrete value bound to every declared variable on every node.
Identity PayloadValidated finite-JSON data deliberately selected by this repo to hold every field that determines a graph config's identity and no incidental runtime or storage field.
Identity DocumentA complete document that carries its own schema name and version, with exactly the shape {schema, schema_version, payload}. This repo selects the identity payload fields inside it and validates the finite JSON and the exact document shape.
Canonical Identity JSONThe canonical JSON this repo renders from a validated identity document, without lossy normalization.
Identity HashThe hash specialization for identity: the full 64-character lowercase SHA-256 value of the canonical identity JSON of an identity document.
Content HashThe hash specialization for content addressing: the full 64-character lowercase SHA-256 value of a complete persisted object or record. Distinct from an identity hash, which comes from canonical identity JSON.
Node (Config)A concrete validated config materialized from exactly one node definition in the umbrella node structure: an executable graph component whose node id is unique within its graph config, carrying a node type reference, its set variable assignments, one node input source per declared runtime input, and its declared output field. Its fields participate in the graph hash; there is no separate node config hash, and it is addressed exactly as (graph_hash, node_id).
Node Input SourceRuntime wiring that maps one declared node input to exactly one graph external input (task.<field>) or one upstream node output. It is part of graph config identity. Static config references are variable assignments, not node input sources.
Graph External InputA runtime graph input supplied through the task.<field> namespace, whether or not the value comes from a caller-specific task identity.
Graph HashThe hash specialization for graph config identity: the full 64-character lowercase SHA-256 identity hash of a graph config, identifying the exact static executable rollout variant. It is derived from the graph config identity document and remains distinct from a content hash.
Graph RunThe deterministic topological interpretation of one graph config with graph external inputs, optional completed node outputs, and a validated node runner callback.
Node OutputA validated JSON-safe output object holding the values a successful node invocation produces. It does not itself enforce that its fields match the node's declared output fields.
Completed Node OutputA caller-supplied prior node output for one node of a graph run, keyed by node id. The interpreter validates it against the graph config — the id must name a node, the value must be a valid node output, and it must carry the node's declared output field — then records it as that node's successful node outcome without invoking the node runner callback. Choosing and persisting completed outputs belongs to the caller; it affects only the run, never the graph hash.
OutcomeThe typed terminal value or state of one logical operation. Success carries its output; typed non-success carries causal-failure or dependency-block evidence. It holds neither attempt history nor provenance and is not itself a result.
Node OutcomeThe node role of outcome: one node's successful, failed, or dependency-blocked terminal state, with the corresponding output or causal evidence.
Terminal NodeThe structural role of the graph's unique sink node, not a node type. On success it produces an ordinary node output that becomes the graph output unchanged.
Graph OutputThe output of a successful graph run: the terminal node's ordinary node output, unchanged and under the same declared output contract. It has no terminal-only shape or reference.
Graph Run ResultThe result for one graph run. It carries graph run identity (the graph hash), the graph external inputs or immutable references that fed the run, the terminal outcome, per-node outcomes and execution order, provenance, and per-attempt failure evidence as references only. It references rather than duplicates the referenced payloads held by an enclosing result, holds no external stage state, and has no separate authoritative persistence path.
ProvenanceFree-form, non-identity metadata describing how a graph run was produced, carried on the graph run result and excluded from every identity payload and from outcomes.
Rollout VariantThe role of exactly one concrete graph config as the static, complete, output-affecting graph and configuration being compared or measured. Its sole identity is that graph config's graph hash, excluding runtime inputs and node outputs. The README's motivating "treatment" and "genome" language maps to this term.

Guarantees

The Graph Hash Is the Whole Config, and Only the Config. The graph hash is the full 64-character identity hash of a graph config's versioned identity document: it covers every static field that determines identity, including open variable assignments, and nothing runtime — no external inputs and no node outputs.
  • Computes the full graph hash through its own identity path — a lowercase 64-character SHA-256 value, with no truncation and no length parameter.
  • Selects the identity payload as exactly the ordered node configs and the single terminal node id, and excludes every runtime and storage field.
  • Owns the graph config identity schema name and version (dr_graph.graph_config, version 1); bumping the version changes every graph hash.
  • Rejects non-finite-JSON variable values rather than coercing them, so NaN or an infinity can never collapse into a colliding identity.
  • Validates that a graph config is a DAG with unique node ids, legal node input sources, and exactly one terminal node that no other node consumes.
  • Interprets a graph in deterministic topological order, resolving each node's inputs from graph external inputs and upstream node outputs and invoking the injected node runner callback.
  • Reuses caller-supplied completed node outputs: a valid entry becomes that node's successful outcome and its node runner invocation is skipped; an unknown node id, an invalid output, or a missing declared output field raises a typed error before any node runs.
  • A failed node marks its downstream dependents blocked; the run produces a typed node outcome for every node and never raises out of node failure.
  • The graph output is the terminal node's node output unchanged, under the same declared output contract, with no terminal-only shape.
  • The graph run result carries per-attempt failure evidence as references only rather than duplicating the referenced payloads, carries no external stage state, and has no separate authoritative persistence path.
  • The node type reference and field type are open strings the interpreter never dispatches on; all type behavior lives in the injected node runner callback.

In vs. Out of Scope

In scopeOut of scope
  • The versioned, variable-bearing graph definition artifact and its materialization into graph configs
  • The native config vocabulary — node structure, node input source grammar, and open variable assignments
  • Structural validation: acyclicity, unique node ids, source legality, exactly one terminal node
  • Finite-JSON and canonical-JSON validation and rendering for identity
  • Deterministic topological interpretation producing node outcomes, graph output, and the graph run result
  • Graph config identity: selecting the identity payload and computing the graph hash
  • Config-assembly builders and inline subgraph composition
  • Error diagnostics
  • Durability, retries, and scheduling
  • Persistence and storage references
  • Prompt, provider, and domain (provider/eval config) semantics
  • The node type behavior behind the node runner callback

Caller-side boundary terms. Three concepts are caller-owned and named here only to fix the boundary: Rollout Result is the enclosing caller-side result that owns provider bodies and attempt records — the graph run result references into it; Provider Call Attempt is a caller-side per-attempt record the graph run result carries references to only; and Platform Stage is caller-side orchestration state the graph run result never holds.

Exported Names

Each row maps a term, or a group of supporting exports, to names in dr_graph.__all__. Every exported name appears exactly once in the names column; there are no aliases or alternate spellings. The primitive terms and the concepts hash, materialization, identity payload, identity document, canonical identity JSON, identity hash, content hash, variable, graph, graph external input, completed node output, outcome, terminal node, graph output, provenance, and rollout variant name concepts or roles without their own exports, so they have no row.

TermExported namesNote
Graph Definition GraphDefinition, NodeDefinition GraphDefinition.materialize binds concrete variable values to every node and returns a GraphConfig; each NodeDefinition declares one node's DAG wiring and required variable names.
Graph Config GraphConfig Construction validates the whole DAG. Exposed as GraphConfig, defined in the spec module.
Node (Config) NodeConfig, NodeFieldSpec, FieldRole The umbrella term is node; the export is NodeConfig. NodeFieldSpec is one declared input or output field, tagged by FieldRole (INPUT or OUTPUT). Its NodeFieldSpec.type_name is the open field-type string, defaulting to "str" (DEFAULT_FIELD_TYPE); the default value is serialized into the identity payload, so changing the default is a hash-breaking change.
Node Input Source NodeInputSourceRef, NodeInputSourceKind, as_node_input_source_ref NodeInputSourceKind is closed at GRAPH_EXTERNAL and NODE_OUTPUT; as_node_input_source_ref parses the task.<field> or node_id.<field> string form into a NodeInputSourceRef.
Graph Hash graph_hash, graph_config_identity_document, graph_config_identity_payload, GRAPH_CONFIG_IDENTITY_SCHEMA, GRAPH_CONFIG_IDENTITY_SCHEMA_VERSION graph_hash is the headline identity operation. graph_config_identity_payload selects the fields that determine identity and graph_config_identity_document wraps them in the versioned identity document named by the two schema constants.
Graph Run execute_graph, resolve_node_inputs, RunNode execute_graph interprets one graph config and also accepts completed node outputs for resume; RunNode is the node runner callback type; resolve_node_inputs gathers one node's inputs from external inputs and upstream outputs.
Node Output NodeOutput The validated per-node output object carrying the node's produced values.
Node Outcome NodeOutcome, NodeOutcomeStatus NodeOutcomeStatus is SUCCESS, ERROR, or BLOCKED; a success carries a NodeOutput, a non-success carries error or block evidence.
Graph Run Result GraphRunResult, GraphRunStatus, NodeError, TerminalError, ClassifiedFailure GraphRunStatus adds PARTIAL to the outcome statuses. TerminalError is the terminal node's non-success snapshot and NodeError the per-node one; ClassifiedFailure is the structured failure shape a NodeError is built from when a node raises an exception. The result's provenance field is provenance and the per-attempt failure-evidence references field is attempt_evidence_refs.
Composition node, graph, inline_subgraph Neutral, provider-unaware builders: node and graph assemble a config; inline_subgraph flattens a subgraph's nodes under a prefix into a parent graph.
External-input validation validate_graph_external_inputs Checks that every task.<field> a graph config binds is among the caller's allowed external fields.
Error diagnostics GraphExecutionError, GraphValidationError, InputResolutionError, NodeExecutionError, CompletedNodeError One taxonomy rooted at GraphExecutionError. GraphValidationError also subclasses ValueError for config-time validation; InputResolutionError, NodeExecutionError, and CompletedNodeError arise during a graph run. The run-summary error snapshots NodeError and TerminalError are listed with the graph run result above.

Scope. This sheet is the authoritative statement of the computation-graph contract dr-graph implements. Exported names match src/dr_graph/__init__.py.
